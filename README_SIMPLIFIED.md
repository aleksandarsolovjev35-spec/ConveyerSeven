# ConveyerSeven Lite — справка по упрощению

> Актуальная документация по запуску и эксплуатации находится в [`README.md`](README.md).

Этот файл сохраняет краткое описание отличий упрощённой реализации, которая сейчас находится в корне репозитория, от предшествующей расширенной версии.

## Что сохранено без изменений по смыслу

- **UI**: тёмная HMI, компоновка, модули JS/CSS и HTML оставлены. Из панели архива
  убраны только поля выбора метода/уровня ZIP.
- **Правила отбраковки**: `domain/defect_rules/*`, геометрия, fail-closed поведение,
  пороги и оверлеи перенесены как есть.
- **Нейросети**: `vision/vision_cluster.py`, карта камер/моделей, обработка одного
  свежего кадра.
- **Маршрутизация деталей**: `domain/part.py` (`GOOD` / `BAD` / `CLEANUP`).
- **Механика распределителя**: `hardware/distributor.py`, `axis.py`, `conveyor.py` и
  контракт `DISTRIBUTOR_LOGIC.md`.
- **Фазы производственного шага**: MOTION / SETTLE / CAPTURE / ANALYSIS / REVIEW /
  PUBLISH, состояние линии и JOG.

## Что упрощено

1. **Одиночный прогон инспекции**
   - Production всегда анализирует один свежий кадр, как и описано в README.
   - Убрана многопрогоновая обёртка голосования; `inspection/consensus.py` оставлен
     как тонкий сборщик метаданных с тем же контрактом для UI.
   - `inspection/inspector.py` работает с одним набором кадров.

2. **Камеры (`vision/camera_manager.py`)**
   - Оставлены: загрузка `camera_mapping.json`, параллельное открытие волнами,
     перебор backend (DirectShow/Media Foundation), MJPG 1280x720, near-black
     проверка, параллельное чтение ролей, дренаж буфера, прогрев.
   - Убраны: многоступенчатое переоткрытие потоков, доказательство FOURCC, циклы
     восстановления и большое число env-тюнингов. Ошибка камеры теперь считается
     фатальной для шага (production-cycle уходит в FAULT, как раньше).

3. **Архив (`inspection/part_archive.py`)**
   - Сохраняются исходные `<ROLE>.jpg`, `<ROLE>_raw.jpg`, `<ROLE>_debug.jpg` и
     `meta.json` в `GOOD/BAD/CLEANUP/part_NNNN/`.
   - Остались `batch.json` и накопительный `stats.json`.
   - Убраны: несколько методов ZIP (`stored/lzma`), detection JSON,
     `samples.jsonl`, dataset/pseudo-label подготовка, файлы `*_runN.*`.
   - При выходе может создаваться один обычный ZIP с дефолтным deflated.

4. **Пороги (`domain/threshold_loader.py`)**
   - Сохранены загрузка `thresholds.json`, секции по камерам, русские подписи,
     группировка для UI, фиксированные количества (2 коротких контакта, 14 TOP),
     пользовательские ярлыки `_label.*` и проверка диапазонов.
   - Удалены длинные описания PARAM_DESCRIPTIONS, часть дублей и ручная схема.

5. **Production cycle (`core/production_cycle.py`)**
   - Удалены хелперы слияния нескольких прогонов; INPUT и SPIDER теперь объединяются
     в один кадр/разметку напрямую.
   - Диагностика «АНАЛИЗ КАДРА» упрощена до одного кадра без цикла по прогoнам.
   - Основная механика движения, пауз, сортировки, архивирования и JOG не менялась.

## Запуск

Как и в оригинале:

```bat
run.bat
```

Зависимости: см. `requirements.txt`.
