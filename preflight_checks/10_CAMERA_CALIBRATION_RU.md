# Калибровка семи камер

Калибратор назначает физические Camera ID ролям линии и создаёт полный `camera_mapping.json`.

## Автоматический запуск

Если `camera_mapping.json` отсутствует, обычный:

```bat
run.bat
```

сначала открывает оконный мастер `КАЛИБРОВКА КАМЕР`. COM-порт, Conveyor и распределитель до завершения мастера не инициализируются.

Для повторной ручной калибровки независимо от наличия JSON:

```bat
run_camera_calibration.bat
```

## Перед началом

- подключить и запитать все семь камер;
- закрыть программы, которые могут удерживать камеры;
- убедиться, что каждая камера может работать в `1280×720`;
- обеспечить видимый, не чёрный кадр каждой камеры;
- остановить производственную линию.

Калибратор не использует COM и не подаёт команды движения.

## Порядок назначения

Поиск идёт в две фазы:

1. **Изолированная проверка** Camera ID `0..9`: каждая камера открывается, проверяется и сразу освобождается — ни одна исправная камера не проигрывает гонку за полосу USB уже открытым соседям. Результат детерминирован: сколько камер исправны вообще.
2. **Одновременное открытие** семи проверенных камер для предпросмотра — ровно так, как это делает production. Камера, потерянная на этой фазе, недоступна и линии: мастер сообщает об этом отдельно (см. «Ошибки»).

Каждая камера получает несколько попыток с полным пересозданием `VideoCapture`: разовый отказ резервирования изохронной полосы на USB лечится повтором, а не таймаутом. Найденные камеры остаются открытыми до конца мастера, поэтому переключение между ними не должно повторно запускать DirectShow. Для продолжения необходимо семь исправных камер.

Число попыток и пауза настраиваются переменными окружения (до запуска `run.bat`):

```bat
set CAMERA_SCAN_OPEN_ATTEMPTS=3
set CAMERA_SCAN_RETRY_DELAY=0.4
set CAMERA_SCAN_PROBE_ATTEMPTS=60
```

Для каждой роли:

1. дождаться живого изображения;
2. кнопками `ПРЕДЫДУЩАЯ / СЛЕДУЮЩАЯ` выбрать физическую камеру;
3. сверить реальный ракурс с названием текущей роли;
4. нажать `НАЗНАЧИТЬ КАМЕРУ`;
5. повторить для следующей роли.

Порядок ролей:

```text
INPUT_LEFT
INPUT_RIGHT
SPIDER_LEFT
SPIDER_RIGHT
SPIDER_IN
SPIDER_OUT
TOP
```

Один Camera ID нельзя назначить двум ролям. Кнопка `НАЗАД` снимает последнее назначение.

## Сохранение

После назначения `7/7` проверить итоговую таблицу и нажать:

```text
СОХРАНИТЬ И ПРОДОЛЖИТЬ
```

Только после этого полный mapping атомарно записывается в `camera_mapping.json`. При автоматическом запуске основное приложение продолжает загрузку самостоятельно.

## Ошибки

Мастер различает два разных отказа:

- **`Найдено исправных камер: N/7 при изолированной проверке`** — камера не отвечает даже наедине с шиной. Проблема в подключении/питании/драйвере/занятости камеры другой программой, а не в USB-полосе.
- **`Одновременно открылось N/7. Камеры [...] исправны поодиночке, но не работают вместе`** — классическая нехватка пропускной способности USB-контроллера: каждая камера рабочая, но одновременно семь не влезают в один корневой хаб.

В обоих случаях:

- mapping не создаётся;
- основное приложение не запускается;
- оборудование исправляется, затем в мастере нажимается **ПОВТОРИТЬ ПОИСК** — окно закрывать не нужно.

Если существующий `camera_mapping.json` повреждён, программа не перезаписывает его автоматически. Удалить или переименовать файл только после осознанного решения и запустить калибратор повторно.

## USB-топология: когда камеры «плавают» от запуска к запуску

Семь камер 1280×720, воткнутые в порты одной материнской платы, почти всегда делят **один** USB-контроллер и один корневой хаб. Тайминг перечисления устройств при каждом старте разный, поэтому и состав «пригодных» камер плавает: кто успел захватить изохронную полосу — тот и работает. Это не чинится настройками программы, чинится железом:

1. **Развести камеры по разным контроллерам.** Задние порты, передняя панель и внутренние колодки часто висят на разных корневых хабах — проверить в Диспетчере устройств (Вид → Устройства по подключению). Лучшее решение для семи камер — PCIe-карта USB 3.0 с независимыми каналами (например, 4 отдельных контроллера на карту).
2. **Убедиться, что все камеры работают в MJPG.** Молчаливый откат `MJPG -> YUY2` поднимает поток одной камеры с ~25 до ~440 Мбит/с и мгновенно съедает всю шину. Согласованный формат каждой камеры печатает `11_RUN_CAMERA_DIAGNOSTIC.bat` — все строки должны быть `MJPG 1280x720@30`.
3. **Отключить энергосбережение USB.** План электропитания → «Временное отключение USB-порта» = Запрещено; в свойствах каждого «Корневой USB-концентратор» снять «Разрешить отключение для экономии энергии». Просадка 5 В при старте семи камер вызывает повторное перечисление устройств и сдвиг Camera ID.
4. **Кабели и питание.** Короткие экранированные кабели, без пассивных удлинителей; при нехватке питания — активный hub с внешним БП.

Точную причину отказа конкретной камеры показывает:

```bat
preflight_checks\11_RUN_CAMERA_DIAGNOSTIC.bat
```

Он проверяет каждую камеру изолированно (полная полоса), затем все семь одновременно (как production), и явно говорит, камера мёртвая или ей просто не хватило шины.
