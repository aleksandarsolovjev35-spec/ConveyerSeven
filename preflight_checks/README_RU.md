# Проверки перед запуском Transporter

Эта папка предназначена для оператора. Внутренняя папка `tests/` содержит regression-тесты разработчика и напрямую оператором обычно не используется.

## Быстрый порядок

После распаковки проекта:

```bat
setup.bat
```

Если `camera_mapping.json` отсутствует, сначала выполнить `run_camera_calibration.bat` либо запустить `run.bat` и пройти автоматически открывшийся мастер. После создания mapping:

```bat
preflight_checks\00_RUN_SOFTWARE_ONLY.bat
preflight_checks\00_RUN_ALL_NO_MOTION.bat
run.bat
```

После открытия UI, но до нажатия START, выполнить чек-лист:

```text
preflight_checks\08_OPERATOR_CHECKLIST_BEFORE_START_RU.md
```

## Разница двух общих запусков

### Software-only

```bat
preflight_checks\00_RUN_SOFTWARE_ONLY.bat
```

Можно выполнять без подключённого станка. Проверяет окружение, JSON-конфигурацию, наличие моделей, загрузку/warmup моделей и автоматизированные тесты.

### Full no-motion

```bat
preflight_checks\00_RUN_ALL_NO_MOTION.bat
```

Дополнительно открывает семь камер и COM-порт. В контроллер отправляется только read-only запрос `I2`. Команды `G1`, `G3`, `G20`, `G27`, `G28` и другие команды движения этим набором не отправляются.

Открытие COM может перезапустить Arduino. Механизм должен находиться в безопасном состоянии, несмотря на отсутствие motion-команд со стороны теста.

## Условия успешного результата

Каждый файл заканчивается строкой `... PASSED`. При первой ошибке общий `.bat` останавливается и возвращает ненулевой exit code.

Нельзя запускать `run.bat`, если любой обязательный этап завершился ошибкой.

## Текущая известная проблема

Если `INPUT_RIGHT` остаётся чёрной, файл `05_seven_cameras_check.py` обязан завершиться ошибкой near-black. Это правильное поведение; обходить его нельзя.

## Камера не прошла preflight: `read returned no frame`

Такая ошибка означает, что камера открылась, но не отдала ни одного кадра за отведённое время. Чаще всего это не поломка камеры, а нехватка пропускной способности USB: семь камер `1280×720` не помещаются на один контроллер, и последняя стартующая камера остаётся без изохронной полосы.

Порядок разбора:

```bat
preflight_checks\11_RUN_CAMERA_DIAGNOSTIC.bat
```

Диагностика проверяет каждую камеру отдельно, под каждым backend, и затем все семь одновременно.

- Камера не отвечает **и поодиночке** — проблема в камере, кабеле или драйвере. Проверить кабель, переподключить, убедиться, что устройство не занято другой программой.
- Камера работает **поодиночке**, но набор из семи падает — не хватает полосы USB. Развести камеры по разным контроллерам, не через один хаб.

Тонкая настройка старта через переменные окружения (значения по умолчанию в скобках):

| Переменная | Что делает |
|---|---|
| `CAMERA_OPEN_CONCURRENCY` | Сколько камер стартует одновременно (3). `1` — строго по очереди |
| `CAMERA_PREFLIGHT_TIMEOUT` | Сколько секунд ждать первый стабильный кадр (5.0) |
| `CAMERA_OPEN_ATTEMPTS` | Число попыток открытия каждой камеры (2) |
| `CAMERA_OPEN_RETRY_DELAY` | Пауза между попытками, с (0.4) |
| `CAMERA_OPEN_TIMEOUT` | Общий предел на открытие всего набора, с (120) |
| `CAMERA_BACKENDS` | Порядок backend-ов, например `dshow,msmf` |

Пример самого щадящего для USB запуска:

```bat
set CAMERA_OPEN_CONCURRENCY=1
set CAMERA_PREFLIGHT_TIMEOUT=8
set CAMERA_OPEN_ATTEMPTS=3
run.bat
```

Ослаблять near-black проверку или проверку разрешения этими переменными нельзя: они влияют только на время и порядок старта.
