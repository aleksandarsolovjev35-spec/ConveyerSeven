# Чек-лист оператора после открытия UI и до START

Выполнять только в `IDLE` или после полного `STOPPED`, когда `IN LINE = 0`.

## 1. Общий статус

- [ ] UI показывает `ONLINE`, не `OFFLINE`.
- [ ] Нет `FAULT`.
- [ ] На пути деталей нет деталей.
- [ ] Физический E-stop доступен оператору.
- [ ] В зоне Conveyor и распределителя нет людей и посторонних предметов.

## 2. Камеры

Если `camera_mapping.json` отсутствовал, перед основным UI должен успешно завершиться оконный мастер `КАЛИБРОВКА КАМЕР` с комплектом `7/7`. Частичный mapping использовать запрещено.

До открытия UI должен пройти:

```bat
.venv\Scripts\python.exe preflight_checks\05_seven_cameras_check.py
```

В открытом UI:

1. Переключить камеры кнопками или клавишами `1–7`.
2. Для каждой роли проверить правильный физический ракурс и отсутствие чёрного/зависшего изображения.
3. Проверить статичную плашку `LIVE · ... FPS`.
4. При необходимости нажать `АНАЛИЗ КАДРА`: LIVE сменится на `АНАЛИЗ`, выбранная камера даст три свежих кадра, а модели и локальные правила проголосуют 2 из 3.
5. После просмотра нажать `ВЕРНУТЬ LIVE`.

```text
INPUT_LEFT
INPUT_RIGHT
SPIDER_LEFT
SPIDER_RIGHT
SPIDER_IN
SPIDER_OUT
TOP
```

- [ ] Все семь камер проверены.

## 3. Модели и правила

До открытия UI должны пройти:

```bat
.venv\Scripts\python.exe preflight_checks\04_model_load_and_warmup.py
preflight_checks\07_AUTOMATED_CODE_AND_UI_TESTS.bat
```

В UI общий блок проверки всех нейронных моделей и камер удалён. Для точечной проверки выбрать камеру и использовать `АНАЛИЗ КАДРА`. Появится компактная сводка model name, средней latency, трёх значений detections и голосов локальных правил. Другие камеры при этом не захватываются; совместный `part_presence` на одной INPUT-камере отмечается как невыполненный.

- [ ] Все 12 model files загружаются и проходят warmup.
- [ ] Автоматизированные rule regression-тесты проходят.
- [ ] Модели нужных камер выполняются без `ERROR`.

## 4. Распределитель

Выполнять по одной команде и ждать полного окончания каждой:

1. `DIST1 HOME` — маркер приходит в 0.
2. `DIST1 OPEN` — маркер плавно проходит к 340.
3. `DIST1 HOME` — маркер возвращается в 0.
4. `DIST2 CLEANUP` — маркер проходит к 340.
5. `DIST2 BAD` — маркер возвращается в 0.

- [ ] Фактическое движение соответствует маркеру UI.
- [ ] Нет удара, заедания, шума или неверного направления.
- [ ] Финально DIST1 находится HOME, DIST2 находится BAD/home.

Перед START программа повторно и автоматически устанавливает это production-положение.

## 5. Коррекция ленты JOG

1. Коротко удержать `←`.
2. Отпустить и убедиться, что лента остановилась.
3. Коротко удержать `→`.
4. Отпустить и убедиться, что лента остановилась.
5. Установить ячейки точно под камеры.

- [ ] Направления соответствуют UI.
- [ ] После отпускания движение прекращается.
- [ ] В process line отображались `JOG_HOLD` и `JOG_STOPPED`.

## 6. Готовность START

Перед нажатием START:

```text
DIST1 = HOME / 0
DIST2 = BAD / 0
IN LINE = 0
FAULT отсутствует
OFFLINE отсутствует
JOG не удерживается
диагностическая операция не выполняется
```

- [ ] START активна.
- [ ] Оператор готов наблюдать первый полный цикл.

## Немедленно не запускать линию, если

- любая камера ERROR или near-black;
- модель ERROR или отсутствует;
- количество моделей не 18/18;
- отсутствует правило;
- физическая лопасть не совпадает с координатой UI;
- JOG продолжает движение после отпускания;
- отображается FAULT/OFFLINE;
- неизвестно фактическое положение детали или ячейки.
